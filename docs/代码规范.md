# 图站代码写作规范

> 版本 v1.0 | 生效日期：2026-08-06 | 适用范围：本仓库全部代码（PHP / Vue / TS / 模板 / SQL / 迁移）
> 冲突规则：本规范与全局规则（`~/.claude/CLAUDE.md`、`~/.claude/rules/`）冲突时，**以更严格者为准**。

## 0. 总则

1. **代码优先**：优先写代码而非长篇解释；关键决策用一行中文注释说明"为什么"，不解释"是什么"。
2. **最小改动**：新功能/修复尽量 ≤3 个文件变更；优先复用已有实现，禁止复制粘贴。
3. **不做未请求的功能**（YAGNI）；不引入无依据的新依赖、不写无效抽象。
4. **完成后必须验证**：运行测试与静态检查，检查所有调用方，确认无悬空引用。
5. **禁止"篇幅限制"式跳过**：代码必须完整输出，不得用"其余代码与上面类似"带过。

## 1. PHP（ThinkPHP 8）规范

### 1.1 编码风格
- 遵循 **PSR-12**：4 空格缩进，行宽 ≤120，`<?php` 声明后不留多余空行。
- 命名：类 `PascalCase`、方法/变量 `camelCase`、常量 `UPPER_SNAKE_CASE`、数据库表/字段 `snake_case`。
- 缩进用空格，不用 Tab；文件末尾保留一个空行；类方法按 `public → protected → private` 排序。

### 1.2 类型与声明
- **所有函数必须声明参数类型与返回类型**（含 `void`、`?type`、联合类型）。
- 优先 PHP 8 原生类型（`string|int`、`?string`），避免冗余的 PHPDoc 重复标注。
- 禁止无意义注释、禁止注释掉的旧代码（用 Git 历史）。

### 1.3 分层架构（Controller → Service → Model）
- **Controller**：只做参数校验、调用 Service、返回响应。禁止写业务逻辑。
- **Service**：业务逻辑唯一载体，可被 Controller / 命令行 / 队列复用。命名 `XxxService`。
- **Model**：仅数据访问、模型关联、访问器/修改器。复杂查询用查询构造器或原生 SQL（需注释原因）。
- 禁止在 Controller 内直接 `new Model` 操作业务；禁止跨 Service 相互 new（用依赖注入）。
- 单文件 ≤400 行，超出按职责拆分。

### 1.4 模块与路由（本项目管理约定）
- 按应用划分：`app/index`（前台 SSR 模板）、`app/api`（用户/前台 JSON 接口）、`app/admin`（后台接口 + Token 鉴权）。
- 路由定义在 `route/`，RESTful 风格：`GET /resources`、`GET /resources/{id}`。
- 后台接口统一 `/admin/*` 前缀，走中间件鉴权。

### 1.5 错误处理与日志
- **禁止裸 `catch`、禁止吞异常**；捕获后必须记录日志并返回用户可读的错误。
- 日志必须包含关键字段：`user_id`、`request_id`、`action`。
- 业务错误统一返回 JSON `{code, message, data}`，`code` 用常量定义，禁止魔法数字。
- API 边界统一捕获异常，控制器内不写 `try/catch`（交给中间件/异常处理），Service 内对 IO 类异常做上下文补充。

### 1.6 安全（本项目硬性要求）
- 所有用户输入经 ThinkPHP **验证器**（`validate`）校验，禁止信任原始输入。
- SQL 一律用查询构造器参数绑定，**禁止字符串拼接 SQL**。
- 前台模板输出自动转义（`{$var}`），用户可控内容（标题/评论）禁止 `raw` 输出。
- **内容分级(level)必须在 Service 层强制校验**：用户 `vip_level >= 内容 level` 才可读，不能只靠前端隐藏。
- 文件上传：校验 MIME + 扩展名白名单（图片 + MP4）；大小限制；存 R2 路径由服务端生成，禁止用用户文件名。
- R2 凭证、数据库密码只存 `config/`，禁止硬编码进代码或提交进版本库。

### 1.7 依赖与工具
- Composer 管理依赖；新增依赖必须在提交说明里写用途。
- 优先 ThinkPHP 框架自带能力与官方包（`aws/aws-sdk-php` 等），不引入无谓第三方。
- 格式化 `php-cs-fixer`/`PHP-CS-Fixer`（若配置），静态检查 `phpstan`/`psalm`（可选，能跑则跑）。

## 2. 后台前端（Vue 3 + TypeScript）规范

### 2.1 技术约束
- Vue 3 + Composition API + `<script setup lang="ts">`，**禁止 Options API**。
- **禁止 `any` / `as any` / `@ts-ignore`**；必须给出明确类型；确需绕过的要注释说明并尽量局部化。
- 组件文件 `PascalCase.vue`；页面放 `pages/`，组件放 `components/`。

### 2.2 目录与分层
- API 请求全部收敛到 `services/`（或 `api/`），组件内**禁止直接写 fetch/axios**。
- 全局状态用 Pinia（`useXxxStore.ts`）；可复用逻辑抽 composables（`useXxx.ts`）。
- 类型定义放 `types/`，与后端接口字段一一对应（可从后端生成）。
- 请求错误统一由 service 层处理并抛出业务异常，组件层只负责展示。

### 2.3 交互状态（必须四态齐全）
- 列表/详情/表单必须处理：**加载中 / 空数据 / 错误（含重试）/ 禁用态**。
- 提交类操作：防重复提交、成功提示、失败提示。
- 错误信息用户可读，禁止裸抛 `Error('...')` 字符串到页面。

### 2.4 UI 风格
- 使用 Element Plus 默认主题与布局，不做视觉"创新"。
- 配色"黑白灰 + 少量主色"，**禁止**渐变、霓虹、玻璃拟态、装饰性动画、emoji 入文案。
- 动画仅限 hover/focus/loading 反馈。

### 2.5 代码质量
- ESLint + Prettier 必须通过；提交前不残留 `console.log` / `debugger`。
- 单文件 ≤400 行，过长拆组件/composable；复用优先，禁止复制粘贴组件。

## 3. 前台页面（TP 模板 + Tailwind + Alpine.js + Plyr）

### 3.1 风格
- Apple/corporate 极简风：大量留白、清晰栅格、强排版层级；白/浅灰背景 + 深色文字 + 少量强调色。
- 禁止渐变/霓虹/玻璃拟态/无意义动画/多字体混用。

### 3.2 技术约定
- 服务端渲染（SSR）利 SEO；轻交互（灯箱、瀑布流、点赞）用 Alpine.js，**禁止**为前台引入重型前端框架。
- 视频播放用 **Plyr**（原生 `<video>` 皮肤）；模板输出自动转义，用户可控内容禁止 `raw`。
- 媒体 URL 由 R2/CDN 域名拼接，禁止在模板硬编码域名。

### 3.3 响应式
- 兼容移动端 / 平板 / 桌面三档断点；触控目标尺寸、可读对比度达标。

## 4. 数据库与迁移

- 表/字段 `snake_case`；索引命名 `idx_xxx`；外键关系命名 `fkey_xxx`。
- 所有表含 `create_time`/`update_time`（TP 自动时间戳字段名），必要表加 `deleted_at` 软删除。
- 等级、状态、类型等枚举字段用 `TINYINT` + **类常量/枚举**，禁止魔法数字散落代码。
- 字段变更必须走 `database/` 迁移文件，禁止直接改线上表结构。
- 查询避免 N+1：`with`/`select_related` 预加载；分页用框架 `paginate`。
- 索引按查询路径设计：`album_id`、`category_id`、`user_id`、`level+status` 等高频过滤组合。

## 5. Git 提交规范

- 提交信息格式：`<type>: <中文描述>`。
  `type ∈ feat | fix | refactor | perf | docs | chore | style | test`
- 一个提交只做一件事；示例：
  - `feat: 新增视频播放页`
  - `fix: 修复游客访问内容页未跳转登录`
  - `refactor: 抽取内容分级校验到 ContentAccessService`
- 禁止提交：调试代码、注释掉的旧代码、硬编码密钥、构建产物（dist/node_modules）。

---

## 6. 提交前检查清单

- [ ] 全部测试通过（PHPUnit / pytest 或对应测试框架）
- [ ] 格式化与静态检查通过（PHP-CS-Fixer / phpstan，或 ESLint / Prettier）
- [ ] 公开函数/类有 Docblock，关键逻辑有"为什么"注释
- [ ] 无硬编码密钥、无残留调试代码、无注释掉的旧代码
- [ ] 未添加未请求的功能；无未完成的 TODO
- [ ] 无重复实现；签名/字段变更后所有调用方已检查
- [ ] 涉及前台的改动已浏览器验证三态（加载/空/错误）+ 移动端适配
- [ ] 涉及权限的改动已验证游客 / 低等级 / 高等级三种用户视角
